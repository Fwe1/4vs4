# 그래픽과 모션

상태 표시: `[확정 날짜]` 사용자가 정함 · `[가정]` Claude가 임시로 넣음, 확인 필요 · `[미정]` 아직 안 정함

## 그래픽 방향
- **3D 모델 + 도트 렌더.** `[확정 2026-11-15]` 이전 계획이던 HD-2D 도트 빌보드는 쓰지 않는다.
- 캐릭터와 지형을 모두 3D로 만들고 툰 셰이더(음영 2단, 외곽선, 림라이트)를 입힌다. 셰이더: `Assets/Prototype/Shaders/Toon.shader`
- 카메라가 장면을 저해상도로 찍고, 픽셀을 뭉개지 않고 그대로 확대해 보여 준다. 보기에는 도트, 속은 3D다.
- 저해상도 크기는 480×270이다. `[가정]` 8명을 한 화면에 담으려고 Claude가 잡은 값이다.
- 실시간 조명과 그림자를 쓴다. 후처리(빛 번짐, 색 보정 등)는 아직 넣지 않았다.

## 카메라
- 전투 중 **고정**이다. `[확정 2026-11-02]`
- 리그는 옆에서 내려다보는 사이드뷰다. 우리 팀이 왼쪽, 상대가 오른쪽이다. `[확정 2026-11-13]`
- 스킬 범위가 잘 보이는 구도를 우선한다. `[확정 2026-11-15]`
- 내려다보는 각도는 약 25°다. `[가정]` 참고 영상의 구도에 맞춰 Claude가 잡은 값이다.

## 캐릭터 에셋 전략
- 큰 머리 SD 비율로 만들지 않는다. `[확정 2026-11-15]` 지금 비율은 약 4.5등신이다. `[가정]`
- 리그 화면에서 캐릭터 키는 약 60px이다. `[가정]`
- 공용 뼈대와 공용 동작을 쓰고, 머리·옷·무기 파츠만 바꿔 끼우는 조립식으로 만든다. `[확정 2026-11-02]`
- 스킬 개성은 모션과 이펙트로 표현한다. 좌우 방향은 모델을 돌려서 처리한다.
- 지금은 기본 도형을 이어 붙인 임시 모델이다. 진짜 모델은 나중에 교체한다. 제작 방법 `[미정]` (후보: VRoid Studio)

## 모션 제작 방식 `[확정 2026-11-15]`
사용자가 모션을 요청하면 이 방식으로 만든다.

- 핵심 자세(준비 → 타격 → 마무리 → 복귀)를 잡는다. 타격 직전은 빠르게, 타격 뒤는 천천히 풀리게 한다.
- 팔다리는 각도를 직접 넣지 않는다. 손발 위치만 정하고 `PuppetRig`의 IK가 무릎과 팔꿈치를 굽히게 한다. 무기는 두 손으로 쥔다.
- 골반 높이, 상체 비틀기, 머리 방향, 양발을 따로 움직여 몸 전체를 쓴다.
- 타격 순간 멈칫(0.05~0.1초), 화면 흔들림, 맞는 쪽의 반응을 넣는다.
- 머리카락과 망토는 몸을 뒤따라 흔들리게 하고, 자세는 12fps로 끊어 재생한다.
- 이펙트는 무기가 실제로 지나간 길에 맞춘다.
- 평타 규칙을 지킨다. 스킬 중이 아닌 캐릭터는 평타를 치고 있어야 한다. ([01-전투규칙.md](01-전투규칙.md))
- 프레임을 캡처해 자세를 점검한 뒤 Unity 플레이 모드로 보여 준다.

## 프로토타입
- **씬:** `Assets/Scenes/PixelPrototype.unity`. 4대4 시작 구도, 전진, 평타, 스킬 모션을 보여 주는 데모다.
  - `LeaguePrototype.unity`, `ToonPrototype.unity`는 방향을 정하기 전의 실험용 씬이다.
- **스크립트** (`Assets/Prototype/`)
  - `Scripts/PuppetRig.cs`: 캐릭터 뼈대. 자세 값을 받아 관절을 돌리고 팔다리를 굽힌다.
  - `Scripts/LancerSkillDemo.cs`: 데모 진행. 자세, 시작 → 전진 → 교전 흐름, 이펙트, 화면 버튼.
  - `Scripts/PixelDisplayFit.cs`: Game 창 모양과 상관없이 도트 화면이 잘리지 않게 맞춘다.
  - `Editor/PixelPrototypeBuilder.cs`: 배경, 캐릭터 8명, 카메라를 다시 만들고 장면을 캡처한다. Unity 메뉴 KongsRaid > Rebuild Pixel Prototype.
- 데모의 캐릭터는 전부 임시다. 실제 전투 시스템(상태 효과, 스탯, 타깃 고정, 밴픽)은 아직 없다.
