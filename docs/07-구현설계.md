# 구현 설계 방향

이 문서는 게임 규칙이 아니라 **코드를 어떻게 짤지**에 대한 방향이다. Claude가 제안했고 사용자가 이 방향으로 진행하기로 했다.

## 상태 효과와 스킬 (2026-11-02)
- **상태 효과는 데이터로 정의한다.** 공용 상태 효과 클래스 하나에 ScriptableObject 같은 데이터를 붙이는 방식이다.
- **태그를 붙인다.** 예: `Shield`, `CC`, `CCImmune`, `Irremovable`
- **판정 함수는 한 곳에만 둔다.** 예: `CanApplyCC()` 가 태그와 전역 규칙을 확인한다.
- **전역 규칙은 설정값으로 둔다.** 예: `ShieldGrantsCCImmunity = true`. 규칙이 바뀌면 설정만 고치고 캐릭터는 건드리지 않는다.
- **스킬은 효과를 참조만 한다.** 특이한 기믹만 작은 동작 클래스로 조립한다(상속 대신 컴포지션). 언리얼 GAS와 비슷한 구조.

## 편성 데이터 (2026-11-15)
데이터를 셋으로 나눈다.

| 종류 | 내용 | 저장 형태 |
|---|---|---|
| 정의 데이터 | 영웅, 스킬, 특성, 전용무기, 전보, 장비가 무엇인지 | 게임에 들어 있는 고정 데이터. 각각 고유 ID가 있다 |
| 편성 정보 | 플레이어가 무엇을 골랐는지 | ID와 숫자만 적은 저장 파일 |
| 전투 데이터 | 결투장에서 실제로 싸우는 캐릭터 | 로딩 때 위 둘을 합쳐 만들고, 전투가 끝나면 버린다 |

**결투장 로딩 순서**
1. 편성 정보를 읽는다.
2. ID로 정의 데이터를 찾는다.
3. 특성, 전용무기, 전보, 장비를 전부 "수정자" 목록으로 바꾼다.
4. 수정자를 스탯과 스킬에 적용해 전투용 캐릭터를 만든다.
5. 전투를 시작한다. 전투 코드는 전투용 캐릭터만 보고, 저장 파일은 다시 읽지 않는다.

**수정자 종류**
- 수치 바꾸기: 쿨다운, 마나 소모, 피해량
- 효과 덧붙이기: 맞은 적에게 상태 효과 추가
- 태그 붙이기: 표식이나 보호막을 해제 불가로
- 시작 조건: 전투 시작 때 효과 부여

**같이 지킬 것**
- 고를 수 없는 조합(같은 스킬의 선택지 둘을 동시에 고르기 등)은 편성 화면에서 저장할 때 검사한다.
- 결투장에 들어간 뒤 편성을 바꿔도 진행 중인 판에는 영향이 없다.
- 상대 봇의 편성도 같은 형식으로 만든다.
